Scam Defense is Thea's scam-specific detection and response system. It runs through AutoMod, combines independent evidence, limits each source to a safe maximum action, and records the result for moderator review.

It covers phishing links, malicious invites, suspicious attachments, QR destinations, identity impersonation, tripwire activity, and coordinated posting patterns. Optional network intelligence can warn your server about infrastructure that qualified communities have already reviewed.

During staged rollout, detection and review can be active while automated enforcement remains observe-only. Saving an action does not override that safety gate.

## Where to configure and review it

| Location | Use it for |
|---|---|
| **Settings → AutoMod** | Turn scanning on, choose detection layers, set the log channel, configure exemptions, and map severity to actions. |
| **Settings → Scam defense** | Review **Effective scam policy** and configure blocked domains, community feed updates, the tripwire channel, network participation, adaptive hardening, and step-up verification. |
| **Scam defense** in the dashboard | Review local findings, source health, **Effective enforcement**, network pulse, campaigns, incidents, and response playbooks. |
| **AutoMod** in the dashboard | Review quarantined findings and enforcement that needs staff attention. |

<Info>
  **Configured** and **effective** are not always the same. A missing permission,
  unavailable provider, plan limit, staged rollout, stale feed, or safety brake
  can keep a saved feature in observe-only mode. Check **Effective scam policy**
  in settings and **Effective enforcement** in the dashboard before testing an
  action.
</Info>

## Enable scam defense

<Steps>
  <Step title="Enable the shared scanning pipeline">
    Open **Settings → AutoMod**, turn on **Enable AutoMod**, and save. Scam
    controls do not process messages while AutoMod is off.
  </Step>
  <Step title="Choose detection layers">
    Keep **Heuristics** on for scam links, invites, attachments, and campaign
    behavior. QR decoding also needs **Image scanning**. Enable the moderation
    screen, name screening, or paid AI classification when you need those
    additional layers.
  </Step>
  <Step title="Set a private log channel">
    Choose a staff-only channel under **Settings → AutoMod → Log channel**.
    Quarantine review and incident alerts need somewhere private to land.
  </Step>
  <Step title="Configure scam controls">
    Open **Settings → Scam defense**. Add local blocked domains, choose a
    community-list mode, and configure optional tripwire and network features.
  </Step>
  <Step title="Start with conservative actions">
    Under **Settings → AutoMod → Actions by severity**, begin with logging or
    quarantine. Review real findings before increasing the response.
  </Step>
  <Step title="Verify effective policy">
    Open **Settings → Scam defense** and inspect **Effective scam policy**. Then
    use **Effective enforcement** on the **Scam defense** dashboard to compare
    each configured severity action with what the runtime may execute.
  </Step>
</Steps>

## Default state for a new server

- The AutoMod master switch starts off.
- Heuristics, the moderation screen, and image scanning are preselected.
- Name screening and AI classification start off.
- The community list starts in **Ask before each update** mode and does not use a fetched version until an admin applies it.
- The tripwire and step-up verification start off.
- Network contribution, network use, and adaptive hardening are preselected, but they cannot process or enforce anything until AutoMod and the operator-managed network rollout are effective. Review these choices before enabling AutoMod.

## Detection pipeline

Thea builds one scannable view from the member's message. It can include message text, forwarded snapshots, link-preview text, embed text, attachment names, sticker names, and poll text. Edits are scanned again.

<AccordionGroup>
  <Accordion title="Links, domains, and invites">
    Thea normalizes hostnames and links before comparison. This catches
    misleading subdomains, Unicode lookalikes, bare hostnames, blocked domains,
    known phishing domains, and Discord invite destinations. Normalization does
    not mean that every external page is fetched. When bounded URL analysis is
    available, it can add redirect-destination and page-fingerprint evidence.
  </Accordion>
  <Accordion title="Attachments and QR codes">
    Attachment metadata is checked for dangerous file types, doubled
    extensions, and misleading names. Thea can decode QR codes from a bounded
    number of Discord-hosted images and pass the destination through the same
    scam checks. Fetches use strict size, timeout, and network-address limits.
  </Accordion>
  <Accordion title="Identity impersonation">
    Join and rename checks look for suspicious names that imitate staff,
    support, administrators, or known brands. Identity findings use hashed
    evidence rather than retaining the screened name.
  </Accordion>
  <Accordion title="Server-local campaign behavior">
    Repeated or structurally similar content across accounts and channels adds
    campaign context over a 15-minute window. Three actors across two channels
    form a suspected campaign; five actors across three channels form a
    confirmed campaign. Campaign evidence alone is capped at log-only. It must
    be corroborated before it can raise a message action, and it never makes
    unrelated member activity punishable.
  </Accordion>
  <Accordion title="Tripwire evidence">
    A regular member posting in a selected channel whose topic includes the
    exact `[thea-tripwire]` marker creates high-confidence evidence. The
    tripwire is capped at quarantine and cannot kick or ban by itself. See
    [Set up a tripwire channel](/moderation/tripwire-channel).
  </Accordion>
  <Accordion title="Optional shared intelligence">
    If network use is enabled and effective, Thea can compare keyed indicators
    with quorum-backed evidence from other participating servers. Your own
    contribution is removed from the lookup. See the
    [Scam Defense Network](/moderation/scam-defense-network).
  </Accordion>
  <Accordion title="Optional AI classification">
    Paid plans can send borderline content to the configured classifier after
    deterministic evidence has been collected. Provider failure does not turn
    into a guilty verdict. Thea continues with the evidence it already has and
    records the degraded state.
  </Accordion>
</AccordionGroup>

## Evidence and action ceilings

Scam Defense does not add correlated signals as if they were independent votes.

- Evidence from the same root cause is deduplicated.
- Trust, freshness, provenance, and actor class are retained in the decision trace.
- Each signal tier has a maximum action.
- The configured severity action cannot raise a finding above its evidence ceiling.
- Discord permissions and global safety limits can lower the action further.
- Staff, bots, and webhooks cannot receive automated punishment.

The result is the strongest action allowed by the evidence, your policy, current permissions, and active safety gates. A weak or unavailable source cannot silently turn into a ban.

Per-message Scam Defense recommendations are limited to allow, log, quarantine, delete, or timeout. The fusion layer never recommends a kick or ban. Those actions exist only through separate manual moderation or repeat-offender escalation.

## Staff, bots, webhooks, and exemptions

Members with **Manage Messages**, **Manage Server**, or **Moderate Members** are treated as staff regardless of role name. Staff, bots, and webhooks can be assessed in observe-only mode so suspicious automation remains visible, but no automated punishment is executed against them.

Configured exempt roles and channels are skipped. Use exemptions when trusted staff need to quote scam content or when a channel intentionally handles samples.

The tripwire is stricter: observe-only actors do not trip it at all.

## Threat feeds and local blocks

Under **Settings → Scam defense**:

- **Blocked domains** adds server-specific hosts. Their subdomains are blocked too.
- **Community scam list** can ask before each update, update automatically, or remain off.

**Ask before each update** does not use a newly fetched version until an admin explicitly applies it. The community list also needs the **Heuristics** layer.

Feed updates are validated before activation. If a refresh fails or becomes stale, **Effective scam policy** reports the condition and Thea continues with healthy local layers.

## Dashboard

The **Scam defense** dashboard is a metadata-only operational view.

Only dashboard collaborators with **Admin** or **Owner** access can open Scam Defense or run incident actions. A Discord moderator role by itself does not grant dashboard access.

The member risk profile shown on a detection is a deterministic context score based on account age and this server's own history. It is not an identity rating or a learned-model prediction.

## Reviews and appeals

Moderator review changes future automation:

- Approving a quarantined finding removes it from incident and retro-hunt action.
- Upholding or escalating a finding provides explicit positive evidence.
- False-positive incident resolution feeds back into network suppression and shadow-learning labels.

Members can use **Request review** from a punishment DM. Appeals return to your server's AutoMod review flow.

## Incidents and response playbooks

Confirmed network evidence can create a local incident when it matches your server's recent metadata. Thea can alert staff, recheck previously logged messages, and temporarily harden new-account link checks.

Moderator-authorized playbooks can delete linked messages, apply bounded one-hour timeouts, or warn exposed channels. They recheck authorization immediately before each action and never ban. See [Review and contain scam incidents](/moderation/scam-incidents).

## Troubleshooting

| Symptom | Check |
|---|---|
| Nothing is scanned | Turn on **Settings → AutoMod → Enable AutoMod**. |
| Findings appear but every effective action is log | Read the reason under **Effective scam policy**. Automated enforcement may be globally disabled or limited to a staged rollout. |
| The network never affects a decision | Confirm network use is enabled. Network intelligence can remain disabled or shadow-only during rollout even while telemetry is visible. |
| The community list contributes nothing | Keep **Heuristics** on. In **Ask before each update** mode, apply the pending version. |
| AI never runs | Check the AI toggle, plan allowance, provider state, and whether the message was borderline. |
| Review precision displays a dash | The dashboard waits for at least 10 human reviews before reporting the rate. |
| A tripwire message does nothing | Follow the [tripwire health checklist](/moderation/tripwire-channel#troubleshooting). |
| An incident playbook does not finish | Check the incident state and Thea's Discord permissions. See [Failed and partial actions](/moderation/scam-incidents#failed-and-partial-actions). |

## Privacy

Scam Defense processes server activity only. It does not monitor direct messages.

Local AutoMod events retain bounded metadata such as event ID, severity, action, timestamps, Discord scope, content length, and a content hash. They do not retain the message body. Shared network observations use keyed indicator digests and rotating contributor pseudonyms instead of raw indicators or server, member, channel, and message IDs.

Local AutoMod events are retained for up to 90 days. Shared network records use separate 14-, 90-, and 180-day limits described in the network guide.

See [Scam Defense Network privacy](/moderation/scam-defense-network#what-leaves-your-server-boundary) for contribution, quorum, public statistics, and retention details.
